# debate-arena · 模型辩论擂台

给一个辩题，让网关里的大模型**自己选角、自己吵、自己判**。

每个模型领一个马甲和人设，按国际大专辩论赛（新国辩）流程打完全场：
一辩立论、三辩盘问、二辩驳论、自由辩论、四辩结辩，裁判长按 内容/语言/配合 三项打分并评出最佳辩手，主席宣读结果。

零依赖，只要 Node.js ≥ 18 和一个 OpenAI 兼容网关。提供两种玩法：**浏览器观赛室**（推荐）与命令行。

## 安装

```bash
git clone https://github.com/trixster2/debate-arena.git
cd debate-arena
cp .env.example .env    # 填入你的 LLMGW_API_KEY（OpenAI 兼容网关的密钥）
```

## Web 观赛室

```bash
node serve.mjs        # 启动后打开 http://localhost:5180
```

在页面里填辩题、选双方持方与回合数，点「开赛」即可**直播整场辩论**：
席位板实时高亮当前发言的模型，实录逐条流入，裁判亮分后自动弹出评分卡；
完赛场次自动归档，历史对局随时回放。

## 命令行

```bash
node debate.mjs "技术让人变得更勤快还是更懒惰" --pro "技术让人变得更懒惰" --con "技术让人变得更勤快"
```

一场完整辩论约 26 次模型调用，耗时十几分钟到半小时不等，取决于网关速度与思考开关。
两种玩法的产物一致，都写入 `runs/<时间戳>/`：

- `transcript.md` —— 全场实录 + 席位表 + 评分表，可直接分享
- `debate.json` —— 结构化数据（每条发言带模型、耗时、token 用量），方便二次统计

## 赛制

| 环节 | 谁上场 | 说明 |
|---|---|---|
| 主席开场 | 主席 | 宣布辩题、席位与流程 |
| 开篇立论 | 正一二三四中的**一辩**，正反方依次 | 定义、标准、三个分论点 |
| 盘问 | **三辩**提问，对方**一辩**应答 | 多轮一问一答 + 盘问小结 |
| 驳立论 | **二辩** | 系统反驳对方框架 |
| 自由辩论 | 二三四辩轮流 | 双方各 150 字短兵相接 |
| 结辩 | **反方四辩**先、**正方四辩**后 | 收束全场、比较得失 |
| 裁判评议 | 裁判长 | JSON 评分（内容与逻辑 40 / 语言表达 30 / 配合与应变 30）+ 口头点评 |
| 宣布结果 | 主席 | 比分、胜方、最佳辩手 |

## 席位分配

默认按人设契合度自动分配（贪心占座）；模型池 ≥ 10 个席位时每个模型只上一个座，池子不够就让最合适的模型兼双帽——兼帽的两个席位是**独立个体**：每次调用无状态，人格与信息全靠各自提示词，同底模也互不知情。当前池 8 个模型：

| 马甲 | 模型 | 人设 |
|---|---|---|
| 锋刃 | deepseek-v4-pro-0813 | 逻辑链长而硬，当面拆论证结构 |
| 说书人 | kimi-k2.6 | 用具体的人和场景讲道理，收尾漂亮 |
| 火种 | minimax-m3 | 金句多节奏快，负责点燃全场 |
| 定盘星 | qwen3.8-27b | 四平八稳，混战里把立场摆正 |
| 疾风 | deepseek-v4-flash-0731 | 反应极快，盘问不留喘息 |
| 明察 | deepseek-v4-flash-vision | 专抓发言里前后不一致的措辞 |
| 杂家 | Agents-A1 | 知识面杂，野路子类比多 |
| 晨星 | Atria-Dawn-Preview | 温和克制控场感好，天生主持腔 |

也可以 `--shuffle` 随机发牌，或 `--assign pro1=qwen3.8-27b,judge=kimi-k2.6,...` 手动排兵。

## 命令行选项

```text
node debate.mjs "辩题" [选项]

  --pro / --con "立场"    显式指定双方持方（推荐，避免"哪个算正方"的歧义）
  --rounds N             自由辩论回合数，默认 3
  --qa N                 每组盘问的问答轮数，默认 2
  --shuffle              随机分配席位
  --seed N               可复现的种子
  --assign k=v,...       手动指定席位模型
  --out DIR              输出目录
  --dry                  只演练席位分配，不调网关
```

## 换自己的模型池

改 `src/models.mjs` 里的 `MODELS` 数组即可（`id` 换成你网关里真实存在的模型名，人设随便编）。
客户端是标准 OpenAI 兼容协议，把 `.env` 里的 `LLMGW_BASE_URL` 指向任何兼容网关（vLLM、各家云 API）都能跑。

## 实现手记（踩过的坑）

- 带思考的模型，`max_tokens` 是**推理与正文共用的预算**，正文可能被推理吃空；本项目在正文为空时回落取推理内容，不浪费已经想好的答案。
- 全场默认**关闭思考**（`thinking: {"type":"disabled"}` + `reasoning_effort: low`）：实测立论从数分钟级降到 4~15 秒，一局轻量对局十几分钟收。想恢复某环节的思考质量，给对应 `call()` 传 `chatOpts: { thinking: true, maxTokens: 16000 }` 即可。
- 裁判评分走 `response_format: json_object`，解析失败自动重试一次。
- 每个模型原则上只占一个席位；"一辩二辩三辩四辩 + 裁判 + 主席"尽量是一批不同的脑子。
- glm-5.3 与 intern-s2 先后被移出默认阵容：前者思考开销大，后者出词慢（关思考后一次立论实测 149 秒，一局两出手占全程 48%）。在 `src/models.mjs` 里增删模型即可，席位分配会自动适应池子大小。

人设是趣味化的，比分是模型给的——胜负结果不代表任何模型的真实能力排名，看个乐。
